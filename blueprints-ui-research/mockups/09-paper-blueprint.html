    Design 8 · paper blueprint Every section in its own notation — one typeset document; values live in the text and are edited where they stand. ⓘ about
  
    
  
    
    
    Direct manipulation, taken further (evolves design 6). A blueprint holds two kinds of things. Identity — the site's title, theme, environment, people — is singular: you don't “manage a list of site titles.” So identity lives on a site card and is edited in place, no category rows: the theme IS the screenshot (click it → a gallery drawer: click a card to activate, search/drop to install more — every installed theme ships), the title IS the headline (the big serif input is the canonical site title — Site options no longer duplicates it), the landing page IS the address bar of the mini browser, the environment IS the spec line (each segment — WordPress · PHP · login · network — is its own click-to-change control), and the users ARE the avatar stack (click → the people drawer; “log in as” any of them, which also drives the spec line).
    
    
    Every section speaks its own notation (evolves design 7's shelves). Plugins are a packing list — small tiles, just icon and name; click one and its ledger line opens below with version, active state, and options edited in place. Content is a table of contents with leader dots; written pages open in the real editor from their title. Files & media stay a directory tree. Fonts are a specimen sheet — every family set in itself. Recipes are numbered instructions whose parameters are blanks filled inside the sentence. Site options, constants, and code are one block of fine print: key, value, click the value to change it. Filled lines read as plain print until you point at them, and sections with nothing in them don't print at all — their ＋ lines gather at the end of the document instead.
    
    
    Everything really ships: ▶ Run compiles pages into wp_insert_post, WXR into importWxr, SQL into runSql, post types & recipes into mu-plugins, roles, constants, language — and when local bytes are bundled, Run boots an embedded Playground and writes them in, with real media-library imports. The JSON tab renders the live blueprint: copy it, download it, or export the .zip bundle carrying the bundled bytes.
    
    
    Every removal is undoable — plugins, themes, users, content, recipes, options, code. A quiet toast offers Undo, and ⌘Z / Ctrl+Z walks back up to 30 removals.
    
    
    Everything still runs: ▶ Run assembles the real blueprint from the card + rows (versions, login, landing page, networking, blogname, plugin slugs, an installTheme step per installed theme with only the active one activating) and launches playground.wordpress.net. Content still opens the real block editor (Playground booted once, pre-warmed, drafts never silently lost).
