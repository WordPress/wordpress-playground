DESIGN 6 ★ Bill of Materials — the site as a parts list, grouped by what users know. about this ▲

This replaces the per-step form. A user doesn't think in installPlugin steps — they think “my site needs these plugins, this theme, this content, these people.” So the editor is a manifest aggregated by category: one Plugins list with a ＋, one Themes list, one Content list, and so on — never one card per item, never a label that echoes the schema. Playground works out the execution order; you just declare what goes in. (This is why v2's declarative shape matters: plugins: [], activeTheme, content: [], users: [] map cleanly to human categories.)

The categories are the user's vocabulary, not the schema's: Site · Plugins · Themes · Content · Users · Settings · Custom code — plus a “＋ Add more” drawer for the long tail (media, fonts, post types, roles, language, multisite, constants) so people discover what a site can contain without being buried in it. The right rail is a live manifest/receipt (“your site includes: 2 plugins, 1 theme, 1 user…”). Custom code is its own category at the end — the escape hatch, clearly labeled, for the 10% no field covers. And the whole thing still round-trips to blueprint.json via the Materials/JSON toggle.
